## 场景题：Uplift Modeling / 红包策略

**题目：** 假设你可以决策在用户付款时针对某种付款方式是否给用户红包、给多少，目标是提升 ROI，你认为比较重要的点是什么？

> **我的回答：** 首先需要确定一个指标，这里可能是用户的 ROI…（当时回答不够完整）
>
> **面试官引导：** 提到了 Two-Learner（T-Learner）的方法——分别对 treatment 组（发红包）和 control 组（不发红包）训练两个模型，用预测转化率之差作为 uplift score 来决策。

**复盘补充（建议思路）：**

1. **明确优化目标**：ROI = 红包带来的增量收益 / 红包成本。关键是衡量"增量"，即 uplift。
2. **用户分群**：
   - **自然转化用户（sure things）**：不给红包也会用该支付方式 → 给了就是浪费
   - **不可转化用户（lost causes）**：给了红包也不会用 → 同样浪费
   - **可被影响用户（persuadables）**：给红包才会转化 → 真正需要投放的人群
   - **反作用用户（sleeping dogs）**：给了红包反而不用 → 避免投放
3. **Uplift Modeling**：训练模型预测 treatment effect（给红包 vs 不给红包的转化率差），而非直接预测转化率。常用方法：
   - Two-Model Approach（T-Learner）：分别建模 treatment / control 组
   - Meta-Learner（S/T/X-Learner）
   - 因果森林（Causal Forest）
4. **红包金额决策**：连续动作空间，可用 CATE（Conditional Average Treatment Effect）建模不同金额的增量效果，在 ROI 约束下做最优金额选择。
5. **在线实验**：A/B test 验证 uplift 模型的效果，关注增量指标而非总体转化。

### 📚 Uplift Modeling / T-Learner 知识梳理

#### 1. ROI 的含义

**ROI = Return on Investment（投资回报率）**

$$ROI = \frac{\text{收益} - \text{成本}}{\text{成本}}$$

在红包策略场景下：

$$ROI = \frac{\text{红包带来的增量收益（如增量 GMV、增量手续费收入等）}}{\text{红包成本（发出去的红包总额）}}$$

举例：花了 100 万红包预算，带来 300 万增量支付金额，ROI = (300-100)/100 = **2.0**。

> **关键点**：单纯追求转化率会导致"撒钱式投放"——给所有人发大额红包，转化率高但亏钱。ROI 才是衡量红包投放效率的核心指标，也是 uplift modeling 要优化的——把有限预算花在真正能被影响的用户身上。

#### 2. 数据构建：需要随机实验（A/B test）数据

将用户随机分流为两组，分别观察转化结果：

| user_id | 特征 X（用户画像/行为） | treatment T | 是否转化 Y |
|---------|----------------------|-------------|-----------|
| u001 | [年龄, 历史支付次数, ...] | 1（发了红包） | 1（转化） |
| u002 | [年龄, 历史支付次数, ...] | 0（没发红包） | 0（没转化） |

- **随机分流是核心**：保证两组用户特征分布一致，转化率差异才能归因于红包而非用户本身差异

#### 3. T-Learner 训练流程

分别用两组数据训练两个 **独立的二分类模型**：

- **Model₁**（Treatment 模型）：只用 T=1 的样本，X → P(Y=1)，预测"发红包时的转化概率"
- **Model₀**（Control 模型）：只用 T=0 的样本，X → P(Y=1)，预测"不发红包时的转化概率"
- 两个模型各自独立，标准 cross-entropy 损失

#### 4. 增量对比：对同一用户估计反事实

不是用户之间对比，而是对 **同一个用户** 用两个模型分别预测：

$$\text{uplift}(x) = P_1(Y=1|X=x) - P_0(Y=1|X=x)$$

| 用户 | P₁（发红包转化率） | P₀（不发转化率） | uplift | 决策 |
|------|-------------------|-----------------|--------|------|
| 小明 | 0.9 | 0.85 | +0.05 | 可投放，增量不大 |
| 小红 | 0.7 | 0.2 | **+0.50** | ✅ 高价值，必须投放 |
| 小李 | 0.8 | 0.8 | 0.00 | ❌ sure thing，不投 |
| 小张 | 0.3 | 0.5 | -0.20 | 🚫 sleeping dog，别投 |

按 uplift 从高到低排序 → 在预算约束内从上往下投放

#### 5. 模型架构选择

表格数据场景，常用：
- **XGBoost / LightGBM**：最常用，表格数据效果好，训练快
- **Logistic Regression**：可解释性强，作为 baseline
- **MLP / DeepFM**：数据量大时可尝试
- 两个模型通常用相同架构，只是训练数据不同

#### 6. 评估方法

> 核心难点：永远无法观测同一个用户的两个反事实结果

**离线评估——Uplift Curve + AUUC：**
- 按 uplift score 从高到低排序
- 横轴：投放比例（0% → 100%）；纵轴：累积增量转化数
- AUUC（曲线下面积）越大越好，好的模型曲线远在随机投放线之上
- **Qini Curve** 类似，归一化方式不同

**在线评估——A/B Test：**
- 实验组：用 uplift 模型决策投放
- 对照组：随机投放 / 全量投放
- 对比指标：相同预算下的增量转化数、ROI、红包预算节省比例

#### 7. T-Learner 优缺点

- ✅ 简单直观，任意分类模型都能用
- ⚠️ 两个模型误差叠加，uplift = 两个大数相减，方差大
- ⚠️ 需要随机实验数据，确保 treatment/control 组可比

#### 8. 其他 Uplift 方法对比

- **S-Learner**：只训练一个模型，把 treatment 标识作为特征 → 更简单但 uplift 信号容易被淹没
- **X-Learner**：在 T-Learner 基础上多一步交叉估计 → 对样本不平衡时效果更好
- **因果森林（Causal Forest）**：非参数方法，直接估计异质性处理效应

### 🎯 用户特征建模（红包场景）

#### 1. 用户画像特征（静态）

| 类别 | 特征举例 |
|------|---------|
| 人口统计 | 年龄、性别、城市等级、职业 |
| 账户信息 | 注册时长、芝麻信用分、会员等级 |
| 资产状况 | 余额宝余额区间、花呗额度、绑卡数量 |

#### 2. 行为统计特征（聚合）

在不同 **时间窗口**（近 7 天 / 30 天 / 90 天）上做聚合：

```
特征模板：{行为} × {聚合方式} × {时间窗口}

举例：
├── 近 7 天支付次数 (count)
├── 近 30 天平均支付金额 (avg)
├── 近 90 天使用花呗占比 (ratio)
├── 近 7 天红包领取次数
├── 近 30 天红包核销率（领了红包后真的用了的比例）
├── 历史对红包的敏感度（有红包 vs 无红包时的转化率差）
└── 最近一次支付距今天数 (recency)
```

> 这类特征是最重要的一层，尤其在树模型（XGBoost）中，手工聚合特征往往比深度模型的自动特征提取更直接有效。

#### 3. 序列特征（深度建模）

用户的行为本质是时间序列，可以用深度模型捕捉行为模式：

| 方法 | 适用场景 |
|------|---------|
| **DIN**（Deep Interest Network） | 对目标 item 做 attention，捕捉与当前场景相关的历史兴趣 |
| **DIEN**（Deep Interest Evolution） | 建模兴趣演化过程（GRU + attention） |
| **Transformer** | 自注意力建模长序列依赖 |
| **SASRec** | 自回归式序列推荐 |

红包场景的序列：用户最近 N 次支付行为（支付方式、金额、是否用了红包、时间间隔等），用序列模型编码成 embedding。

#### 4. 上下文特征（实时）

```
├── 时间特征：星期几、几点、是否节假日、是否月初/月末（发工资）
├── 当前订单：支付金额、商品类目、商户类型
├── 渠道特征：APP / 小程序 / 线下扫码
└── 实时状态：当前可用支付方式列表、账户余额是否充足
```

#### 5. 交叉 & 组合特征

```
手动交叉：
├── 芝麻信用分 × 订单金额区间   → 高信用大额用户可能不需要红包
├── 历史红包核销率 × 红包金额   → 对红包敏感的用户给小额就够
└── 支付方式偏好 × 当前支付方式  → 本来就爱用花呗的人，花呗红包没意义

自动交叉（模型层面）：
├── FM / DeepFM：自动学习二阶特征交叉
├── DCN（Deep & Cross Network）：显式高阶交叉
└── AutoInt：用 attention 做特征交互
```

#### 6. 整体建模架构

```
┌─────────────────────────────────────────────────┐
│                  Model Input                     │
│                                                  │
│  ┌──────────┐ ┌──────────┐ ┌──────────────────┐ │
│  │ 用户画像  │ │ 上下文   │ │ 行为序列         │ │
│  │ (dense)  │ │ (dense)  │ │ [a₁, a₂, ..., aₙ]│ │
│  └────┬─────┘ └────┬─────┘ └────────┬─────────┘ │
│       │            │           Transformer/DIN   │
│       │            │                │            │
│       │            │          sequence embedding │
│       ▼            ▼                ▼            │
│  ┌──────────────────────────────────────┐        │
│  │        Concat / Cross Network        │        │
│  └──────────────────┬───────────────────┘        │
│                     │                            │
│                  MLP layers                      │
│                     │                            │
│                     ▼                            │
│              P(Y=1 | X)  转化概率                 │
└─────────────────────────────────────────────────┘

T-Learner: 这个架构复制两份，分别用 treatment/control 数据训练
```

#### 7. 对 Uplift 特别重要的特征

不是所有特征对"预测转化率"重要就对"预测 uplift"重要。Uplift 模型特别关注 **异质性处理效应相关的特征**：

```
关键特征（与 uplift 强相关）：
├── 历史红包敏感度         → 直接反映用户是否会被红包影响
├── 价格敏感度指标         → 历史是否倾向用优惠券/折扣
├── 该支付方式的使用频率    → 高频用户 = sure thing，uplift 低
├── 新用户 vs 老用户       → 新用户更可能被影响
└── 账户余额 / 信用额度    → 经济约束可能影响 treatment effect

不太有用的特征（对转化重要但对 uplift 无区分度）：
├── 性别、年龄            → 可能两组转化率都高/都低，差值为 0
└── 设备型号              → 影响转化但不太影响"红包是否能改变行为"
```

### 🌐 Uplift Modeling 应用场景

> **核心适用条件**：干预有成本 + 用户存在异质性 + 需要决策"给谁做/不给谁做"

#### 1. 金融 & 支付（蚂蚁、美团、京东金融）

| 场景 | 干预 (Treatment) | 目标 |
|------|-----------------|------|
| **红包 / 优惠券投放** | 发红包 vs 不发 | 提升支付转化 ROI |
| **信贷营销** | 推送贷款广告 vs 不推 | 提升放贷量，控制获客成本 |
| **花呗 / 白条开通** | 主动邀请开通 vs 不邀请 | 提升开通率，避免打扰 |
| **逾期催收** | 打电话催收 vs 不打 | 最小化催收成本下最大化回款率 |
| **保险推荐** | 推送保险产品 vs 不推 | 避免过度打扰导致用户流失 |

#### 2. 电商（淘宝、京东、拼多多、美团）

| 场景 | 干预 | 目标 |
|------|------|------|
| **优惠券发放** | 给券 vs 不给 / 给多少 | 最大化增量 GMV，控制补贴预算 |
| **促销活动触达** | Push 通知 vs 不推 | 提升活动参与率，减少打扰 |
| **满减策略** | 满100减20 vs 满200减30 | 找到最优满减门槛 |
| **用户留存** | 发召回红包 vs 不发 | 对流失用户精准干预 |

#### 3. 用户增长 & 留存（几乎所有互联网公司）

| 场景 | 干预 | 目标 |
|------|------|------|
| **流失召回** | 发短信/Push/红包召回 vs 不发 | 只召回"能被召回的人"，节省预算 |
| **新用户激励** | 新手任务奖励 vs 不给 | 区分自然留存 vs 需要激励的用户 |
| **会员升级** | 推荐开会员 vs 不推 | 避免打扰已经会开的用户 |

#### 4. 广告（字节、腾讯、Google、Meta）

| 场景 | 干预 | 目标 |
|------|------|------|
| **广告投放** | 展示广告 vs 不展示 | 衡量广告的真实增量效果（incrementality） |
| **出价策略** | 高出价 vs 低出价 | 在 ROI 约束下最大化增量转化 |
| **频次控制** | 展示 3 次 vs 5 次 | 找到最优曝光频次 |

> Google / Meta 内部大量研究 "ad incrementality"，本质就是 uplift。这也是为什么蚂蚁这个岗位叫"搜索推荐**广告**算法"却问 uplift 的原因。

#### 5. 游戏 & 医疗

- **游戏**：付费引导（首充礼包）、防流失（发补偿活动邀请）
- **医疗**：个性化治疗 → uplift 的学术起源（异质性治疗效应 HTE）

> **一句话总结**：有预算约束的精准干预问题 = uplift 的主战场。传统做法预测"谁会转化"会浪费预算在 **不投也会转化的人** 身上，uplift 的核心价值是找到 **"被干预才会转化"的增量用户**。

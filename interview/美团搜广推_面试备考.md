## 二、项目深挖：华为双塔召回系统

> 🎯 这是面试官最可能花时间的模块。先背熟「完整介绍文稿」，再对着「追问Q&A」做口头练习。

---

### 📢 完整项目介绍文稿（面试时直接说这版，约3分钟）

> **背景：**
> 我在华为上海研究所实习时，负责的核心项目是 5G 基站的参数自动匹配系统。基站出现异常后，工程师会提交一份 DTS 问题单描述故障现象，然后需要人工从约 1.2 万条 MO 参数里找出相关参数，再做发散测试定位根因。这个过程完全依赖经验，效率很低。我的任务就是把它自动化——问题本质是**信息检索**：给定一条 query（问题单），从 1.2 万条候选参数里召回最相关的结果。

> **系统设计——两路并行：**
> 我设计了两路并行召回。第一路是**规则匹配**：从问题单的 HTML 脚本字段里抽取参数名关键词，用 Levenshtein 编辑距离与参数库匹配，设相似度阈值过滤，每条问题单平均返回约 **15 条**候选。这一路精确度高，但局限明显——只能抓脚本里明文出现的参数名，对于问题描述里用语义表达的内容（比如"上行带宽异常"而非直接写参数名）完全失效。
>
> 第二路是**语义向量匹配**：用微调后的双塔模型把问题单和参数描述分别编码进同一向量空间，余弦相似度检索 Top-50。这一路能覆盖规则方法漏掉的语义相关参数，但引入的噪声也更多。两路互补——规则方法保精度，语义方法保覆盖。

> **训练数据构建——闭环 + 自动化难负例挖掘：**
> 语义模型需要标注数据，但人工全量标注 1.2 万条参数成本极高。我用了一个**自动化闭环**：把规则方法输出的 `<问题单, 参数>` 对直接作为正样本。从约 80 条历史 DTS 单里，提取了约 **500 个高质量正样本对**。
>
> 难负例也是**全自动挖掘**，不需要人工标注：用微调前的预训练模型对每条问题单检索 Top-20，把规则方法确认的正样本排除，剩下排名最靠前的 **2 个**就是难负例——预训练模型打高分但实际不相关，正是"看起来像、实际不是"的混淆参数。比如描述"上行 EARFCN 异常"的问题单，模型可能把"下行 EARFCN 参数"排很高，但它实际上不是这条单的根因，这就是一个好的难负例。
>
> 500 个正样本 × 每个配 2 个难负例 = **约 1000 个 Triplet** 用于训练。
>
> 训练配置：预训练模型选 `Paraphrase-multilingual-MiniLM-L12-v2`（5G 参数名是英文、问题单是中文，需要跨语言对齐）；Triplet Hinge Loss，margin=0.3；5 个 epoch，batch size 128，lr 2e-5；网格搜索 + Early Stopping 找最优超参。

> **结果融合与最终输出：**
> 两路取并集：规则方法平均返回 **15 条**，语义 Top-50 中有约 **40 条**是规则方法没覆盖到的新参数（其余 10 条左右有重叠），最终每条问题单的候选池约 **50-60 条**。
>
> 融合用**三档优先级**：①两路都召回到的参数优先级最高（双重印证）；②只有规则方法召回的次之；③只有语义方法召回的优先级最低但覆盖长尾。下游发散测试成本高，工程师按优先级依次跑，不需要把 50-60 条全部测试。

> **验证结果：**
> 准备了 **20 条人工标注的 DTS 单**作为验证集，共标注了 **130 个**相关参数。
>
> - **纯规则基线**：覆盖其中 67 个，覆盖率 **51.5%**——只能捕获脚本中明文提及的参数
> - **完整系统（两路合并）**：覆盖 97 个，覆盖率 **74.6% ≈ 75%**
>
> 20 条单中，16 条覆盖率在 70% 以上；有 2 条困难 case 覆盖率很低——一条问题单描述极短缺乏语义信息（覆盖率 0%），另一条涉及多子系统交叉参数较分散（覆盖率约 33%）。

### ⚠️ 两个术语解释（面试时要说清楚）

**"覆盖率"是什么意思？**
> 覆盖率 = Recall（召回率）。对一条 DTS 单，人工标注了 N 个真正相关的参数，如果系统召回的候选集里包含了其中 M 个，覆盖率就是 M/N。注意它衡量的是"有没有漏掉"，不管候选集里有多少噪声（系统可能返回 70 条，其中 4 条是真正相关的，覆盖率就是 4/4=100%，但精确率只有 4/70≈6%）。**我们这个系统是召回系统，优先保 Recall，精度由下游人工复核兜底。**

**两路结果融合的"优先级"是怎么回事？**
> 不是"置信度加权"（这个说法不准确）。实际是一个**三档优先级规则**：
> - **第一档**：两路都召回到的参数——两个独立方法都认为它相关，可信度最强，优先发散
> - **第二档**：只有规则方法召回到的——依赖明文匹配，精确但覆盖窄
> - **第三档**：只有语义方法召回到的——扩展了长尾覆盖，但噪声更多
>
> 下游发散测试资源有限（每次测试需要搭建环境、跑自动化用例），所以按这个优先级依次发散，而不是把 50-80 条全部跑一遍。

### 预测追问 & 标准答案

**Q1：你说有两路方法，最终结果怎么融合的？**
> A：两路都输出 `<DTS单, MO参数>` 配对，取并集合并。规则方法每张单返回约 15 条，语义 Top-50 中有约 40 条是规则方法没覆盖到的新参数（约 10 条有重叠），最终候选池在 **50-60 条**左右。融合用的是**三档优先级规则**，不是加权平均——两路都召回到的参数最可信排第一档；只有规则方法的排第二档（精确但覆盖窄）；只有语义方法的排第三档（覆盖长尾但噪声更多）。下游发散测试成本高，按优先级依次跑，不用把 50-60 条全部测。

**Q2：为什么用 Paraphrase-multilingual 而不是直接用 BERT？**
> A：两个原因：①5G参数库中参数名是英文，DTS问题单是中文描述，需要**跨语言语义对齐**能力，Paraphrase-multilingual 专为多语言语义相似度任务预训练，天然适合；②MiniLM 参数量小（约 66M），推理速度快，在1万+候选的在线检索场景下延迟可控。用 BERT-base 则缺少多语言能力，bert-multilingual 的语义对齐质量也不如专门训练过的 Paraphrase 系列。

**Q3：Triplet Loss 里的 margin 怎么设的？有没有调过？**
> A：通过网格搜索调的，我们试了 0.1、0.2、0.3、0.5 几个值。margin 太小时模型没有足够的区分压力，正负样本的 Embedding 距离不够开；margin 太大则训练不稳定，loss 难以收敛。最终选了 0.3，配合 lr=2e-5、batch=128，效果最好。Early Stopping 在验证集上监控覆盖率，防止过拟合。

**Q4：失败的那两个case（0% 和 33%）是什么原因，分析过吗？**
> A：分析过。DTS2024102815860（覆盖率0%）是因为这条问题单的描述极其简短，缺乏语义信息，无论是规则还是语义方法都无法有效提取特征。DTS2025020721458（33%）则是问题单涉及多个子系统的交叉参数，相关参数分散在不同MO下，召回到了其中3个但漏掉了6个——这暴露了单向量表示对复杂多意图查询的局限性，后续可以考虑**查询意图分解**，拆分成多个子查询分别召回再合并。

**Q5：验证集只有10条，结果有代表性吗？**
> A：这是这个项目最大的局限性，我也在报告里承认了这一点。10条是当时人工标注的上限（标注成本高）。为了尽量保证可靠性，我们选取了覆盖不同业务场景、不同问题类型的10条，而不是随机抽取；同时两路方法都基于同一验证集评估，保证了方法间对比的公平性。如果继续优化，应该扩大标注集，并引入 bootstrap 置信区间估计。

**Q6：这个经历和推荐系统的关系？（面试官可能会问你是否了解下游应用）**
> A：这个系统的本质就是推荐系统的召回层——从大规模候选集里快速找到最相关的结果。在推荐系统里，user query 是用户画像+上下文，候选是商品/内容；在我的系统里，query 是故障描述，候选是MO参数。**双塔结构、Triplet Loss、难负例采样**这三个核心技术点在工业级推荐系统的向量召回里完全通用，这也是我觉得这段经历对搜广推岗位有直接价值的原因。

## 三、项目深挖：ReEnsemble（强化学习多模型集成）

> 🎯 JD明确提到"强化学习"，这个项目是你简历里与之直接对应的唯一经历，要能主动提出来并讲清楚。

### 项目背景（一句话）

> 针对新闻政治立场预测任务（左/中/右），设计了一个**基于强化学习的动态集成框架**，用 Actor-Critic 自适应地对 BERT、LSTM、SVM 三个基础模型的输出进行逐样本加权融合。

### 核心架构

```
输入：新闻文章文本
       ↓ (spaCy提取动词/形容词/副词)
  ┌────────────────────────┐
  │  BERT  │  BiLSTM │ SVM │   ← 3个异构基础分类器，独立训练
  └────────────────────────┘
       ↓ 各输出 3维 logit 向量
  s = [z_BERT; z_LSTM; z_SVM] ∈ R⁹   ← 状态向量
       ↓
  Actor Network πθ(s)
       ↓ softmax
  权重 [w1, w2, w3]   ← 针对每个样本动态生成
       ↓
  z_fused = Σ wk · z(k)   ← 加权融合
       ↓
  argmax(softmax(z_fused))  ← 最终预测
```

**训练流程（三阶段）：**
1. 各自用交叉熵损失独立训练 BERT、BiLSTM、SVM
2. 在验证集上提取三个模型的 logit，构建状态向量
3. 用 **DDPG**（Deep Deterministic Policy Gradient）训练 Actor-Critic：
   - Reward：`r = 1 - CrossEntropy(softmax(z_fused), y)`（预测越准、越自信，奖励越高）
   - Critic 最小化 Q 值预测误差，Actor 最大化期望 Q 值

### 实验结果

| 模型 | Accuracy | Macro-F1 |
|------|----------|----------|
| BERT | 0.4554 | 0.4195 |
| LSTM | 0.4438 | 0.3097 |
| SVM  | 0.4023 | 0.3574 |
| Stacking | 0.4608 | **0.2103** ← 崩了 |
| Majority Vote | 0.4585 | 0.3856 |
| **ReEnsemble** | 0.4592 | **0.4162** ← 集成方法最高 |

> **关键结论：** Stacking 准确率最高但 Macro-F1 极低（0.21），说明它严重倾向多数类，实际失效。ReEnsemble 的 Macro-F1 在所有集成方法中最高，类别均衡性最好。

---

### 预测追问 & 标准答案

**Q1：整体准确率只有 46%，是不是效果很差？**
> A：这是一个**三分类任务**，随机猜测基线是 33%，46% 是在没有任何外部知识的情况下纯从文章文本预测政治立场，任务本身极其困难——政治倾向往往藏在细微措辞里，即使人类标注者也有分歧。我们选择 **Macro-F1 作为核心指标**，因为测试集类别不平衡（Right 占 46%），准确率会被多数类主导，Macro-F1 更能反映模型在各类别上的均衡表现。

**Q2：为什么用强化学习而不是直接 Stacking 或加权平均？**
> A：Stacking（线性元学习器）是静态融合，对所有样本用同一套权重。但不同样本的"最佳融合方式"是不同的——有些文章 BERT 语义理解更准，有些文章 LSTM 的序列模式更有效。**RL 的优势是逐样本动态加权**，Actor 根据三个模型的 logit（即它们的"置信度分布"）来决定这次该信谁。实验也验证了这一点：Stacking 的 Macro-F1 只有 0.21，而 ReEnsemble 达到 0.42。

**Q3：为什么选 DDPG？动作空间是连续的吗？**
> A：是的，动作空间是**连续的**——Actor 输出三个模型的软权重 [w1, w2, w3]（经 softmax 归一化为概率分布），这是一个连续动作空间，DQN 等离散动作算法无法直接使用。DDPG 专门设计用于**连续动作空间的确定性策略学习**，Actor 直接输出确定性权重，Critic 估计 Q 值来引导 Actor 更新，适合这个场景。

**Q4：Reward 函数是怎么设计的？有没有稀疏奖励问题？**
> A：`r = 1 - CrossEntropy(softmax(z_fused), y)`，这是一个**稠密奖励**——每个样本都有即时回报，不存在稀疏问题。用 1 减去 CE loss 的好处是：不仅鼓励预测正确，还鼓励预测置信度高（CE loss 越小奖励越大）。如果改成"预测对得 1 分否则 0 分"的稀疏奖励，训练信号会更弱，收敛慢。

**Q5：这个项目和推荐系统有什么关联？**
> A：有两个层面的关联。第一，**多模型动态融合的思路**和推荐系统的 MMOE 非常相似——MMOE 的 Gate 网络按任务动态分配 Expert 权重，本质上也是"根据输入决定信谁"；区别是 MMOE 用监督学习训 Gate，我们用 RL。第二，**多路召回融合**场景同样面临"不同召回路的分数量纲不一致"问题，如果把每路召回当做一个"基础模型"，用类似方法动态加权也是可行的思路。这说明我对模型融合有跨场景的理解，不局限于单一任务。

**Q6：有哪些局限性？如果继续做会怎么改进？**
> A：三个局限：①**基础模型能力上限制约集成上限**，BERT 的 F1 是 0.42，集成后也差不多——应该换更强的基础模型（如 RoBERTa、DeBERTa）；②**训练数据在验证集上**，存在分布问题，可以用 bootstrap 或交叉验证估计置信区间；③**Action Space 是权重而非直接预测**，论文结论部分也提到，可以让 Actor 直接输出类别概率分布，突破基础模型的预测边界。

## 四、项目深挖：科研经历

### ASME 论文：CNN-LSTM 喷雾图像预测

**项目介绍**

我这个项目是关于内燃机中喷雾形态预测的，背景是在使用多组分燃料进行喷射时，容易发生闪沸和喷雾塌缩的现象，这种现象会影响效率和排放控制。

为了解决传统的物理实验成本高、难以覆盖所有燃料配比的问题，我们构建了一个基于深度学习的预测框架，使用CNN-LSTM的结构来预测不同燃料混合比例下的喷雾图像形态。模型输入是已有测试条件下的图像序列，输出是目标燃料比例下的喷雾图像。

我们做了两类预测任务：插值预测和外推预测，分别对应于在已有实验范围内和范围之外做图像生成，预测准确率在93%～98%之间。

我的主要工作是设计整个深度学习网络结构、图像预处理、训练方案调优以及模型评估指标的构建。我们还通过物理量（比如喷雾尖端位置的加权距离）来量化预测效果，保证模型结果是有物理意义的。

一句话版本：在过去的科研项目中，我用 CNN-LSTM 构建了一个图像预测模型，用于预测不同燃料混合比例下喷雾图像的形态，实现了插值和外推任务，最高准确率达到 98%，我主要负责算法设计与训练评估部分。

**预测追问 & 答案**

**Q：为什么用 LSTM，而不是直接用 Transformer or 3-D CNN？**
> A：我选择LSTM是因为它在处理序列依赖方面非常成熟，尤其是通过门控机制（输入门、遗忘门和输出门）能够有效地保留图像序列之间的关联性。虽然这些图像在时间上不是严格意义的连续帧，但他们在燃料组分或环境条件连续变化的设计下，具有物理上的“序列性”。 相比之下，3D-CNN更适合直接处理视频或者体积数据，但在我们项目中，每一组图像对应的实验条件是离散采样的，3D-CNN地连续建模假设不完全适用。而Transformer虽然在序列建模中表现出色，尤其在长距离依赖建模上有优势，但它需要的数据规模更大，计算资源需求也更大。在LSTM已经有很好的表现且数据规模较小的情况下，我们选择了LSTM。

**Q：模型结构？**
> A：模型采用 CNN Encoder + LSTM + Decoder 的结构，整体是一个图像序列到图像的预测框架。首先，每张输入图像通过 CNN Encoder 提取高层次 空间特征，结构上使用了 Conv + BatchNorm + LeakyReLU 的组合，最后输出一个一维向量表示这张图像。然后，这些图像对应的一维特征向量被作为时序输入传给 LSTM 网络。LSTM 能够建模图像之间的顺序关系，输出一个状态向量 h。最后，我们把 h reshape 成一个 feature map，然后输入 Decoder 网络还原为图像。Decoder 采用多层 Transposed Convolution + BatchNorm + ReLU 的结构，使得最终输出和原图大小一致。这样的设计能让模型同时捕捉图像的空间信息和跨时间的变化模式，在插值和外推任务上都取得了 93%~98% 的准确率。

**Q: 你们是用图片预测图片，那请问你是怎么设计损失函数的？有没有考虑过使用结构性损失（比如 perceptual loss 或 SSIM）来提升生成图像的质量？你怎么衡量你生成的图像是不是“好”？**
> A: 我们使用的是均方误差（MSE）作为训练过程中的主损失函数。具体做法是：我们将预测图像和标签图像在每一个像素位置上进行逐一比较，计算其像素值的平方误差，然后对所有像素取平均。因为我们的图像是灰度图，像素值在0-255之间，所以这个误差可以比较直观地衡量两张图之间的整体差异。 我们当时没有引进结构性损失函数（比如perceptual loss或者SSIM），主要是因为我们任务的目标是预测喷雾形态的物理特征，而不是提升图像的视觉效果，此外，我们数据本身的纹理信息比较简单，不像自然图像那样需要高阶结构的感知能力。 为了从物理角度更好的评估预测图像的准确性，我们还引入了一个自定义的指标，叫做光强加权的喷雾尖端距离。它衡量的是从喷嘴到喷雾最远端的像素距离，并且加权考虑了每个像素的光强。这个指标可以有效反映喷雾是否发生了塌缩，因为我们认为它比传统图像相似度指标更能代表模型在物理任务上的预测能力。

### Physics of Fluids 论文：XGBoost 特征消融

**核心一句话：** 通过5组 XGBoost 配置的特征消融实验，将预测精度从 79% 提升至 93.4%，并推导出跨工况泛化公式。

**预测追问 & 答案**

**Q：XGBoost 的消融实验是怎么设计的？**

## 五、八股 QA：召回与排序模型

> 🎯 按"30秒核心答案"的格式背，面试时先说核心，再展开细节。

### Q1：双塔模型的局限性是什么？

**核心答：** 无法使用 user-item 交叉特征，训练和预测需保持塔分离，导致用户和物品之间的实时交互信号很难利用。

**展开：** 解决方案是在召回后加粗排层（轻量交互模型），或在双塔内部引入 Late Interaction（如 ColBERT：每个 token 的 Embedding 做最大相似度聚合）。

---

### Q2：MMOE 解决了什么问题，Gate 的作用是什么？

**核心答：** 解决多任务学习中不同任务梯度方向冲突（seesaw problem）。每个任务有独立 Gate，对多个 Expert 的输出做加权融合，使不同任务可以选择性地利用不同专家的知识。

**展开：** `output_k = Σ gate_k(x)[i] × expert_i(x)`。相比 Shared-Bottom，MMOE 在任务相关度中等时效果更好；任务差异极大时可用 PLE（每个任务有专属Expert）。

---

### Q3：DIN 的核心思想？

**核心答：** 用户对目标 item 的兴趣是多样的，应该对历史行为做**目标感知的注意力加权**，而非简单 Pooling。

**展开：** 注意力分数 `s_i = MLP([e_hist_i, e_target, e_hist_i - e_target, e_hist_i ⊙ e_target])`，最终用户表示 `v_u = Σ s_i × e_hist_i`。

---

### Q4：负样本采样为什么重要？常见策略？

**核心答：** 召回模型在全库做检索，负样本必须覆盖全分布，而不能只用曝光未点击（SSB偏差）。

**策略：**
- 全局随机采样：覆盖全库分布，但难度低
- 热度加权采样：`P(i) ∝ freq(i)^0.75`，打压热门 item 过采样
- Batch 内负采样：高效，但 hard negative 少
- Hard Negative：模型打高分但实际不相关的样本，提升区分度（你在华为做过！）

---

### Q5：多路召回结果如何融合？

**核心答：** 各路召回分数量纲不同，不能直接比较。常用：
1. **RRF（Reciprocal Rank Fusion）：** `score = Σ 1/(k + rank_i)`，按排名融合
2. **归一化后加权求和**
3. **统一粗排打分：** 用一个轻量模型对所有召回结果重新评分（最推荐）

---

### Q6：Position Bias（位置偏差）是什么？怎么解决？

**核心答：** 用户点击行为受 item 展示位置影响——排在前面的 item 被点击，不一定是因为质量好，而是因为位置曝光。直接用原始点击日志训练会学到位置偏差而非真实偏好。

**解决方案：**
- **PAL（Position-bias Aware Learning）：** 将点击拆解为"被注意到"×"真实相关"，对曝光位置单独建模并在推理时去掉位置塔
- **逆倾向加权（IPS）：** 用曝光概率的倒数对样本加权，纠正选择偏差
- **随机展示实验：** 在小流量上随机打乱位置收集无偏数据，用于模型校正

---

### Q7：SSB（样本选择偏差）问题是什么？

**核心答：** CVR 预估模型只用"点击后是否转化"训练，但上线时要对全部曝光样本打分——训练空间（点击样本）远小于预测空间（全曝光样本），导致分布不匹配。

**解决：** ESMM（全空间多任务模型）：在全样本空间联合训练 pCTR 和 pCVR，通过 `pCTCVR = pCTR × pCVR` 约束，让 CVR 模型间接在全空间学习，消除 SSB。

---

### Q8：Transformer Self-Attention 复杂度及优化？

**核心答：** 标准 Self-Attention 时间和空间复杂度均为 **O(n²d)**，n 是序列长度，d 是维度。长序列时计算/显存开销极大。

**优化：**
- **Sparse Attention：** 只计算局部窗口或固定步长的 attention（Longformer）
- **Linear Attention：** 用核函数近似 softmax，复杂度降至 O(nd)
- **FlashAttention：** IO 感知分块计算，减少 HBM 读写，速度 2-4x，不改变数学结果
- **SIM（推荐场景）：** 先用 Faiss 检索最相关的 Top-K 历史行为，再做精细 Attention

---

### Q9：特征工程：ID Embedding 的维度怎么选？

**核心答：** 经验公式 `dim ≈ min(50, cardinality^0.25 × c)`，通常取 16~256。维度过小欠拟合，维度过大参数爆炸且数据不足时过拟合。

**其他特征处理要点：**
- 低频 ID（出现次数 < 阈值）映射到 `<UNK>`，防止噪声 Embedding
- 连续特征：Log 变换处理长尾分布；等频分桶离散化后接 Embedding
- 序列特征：Pooling（简单）→ Target Attention（DIN）→ 长序列用 SIM 先检索再 Attention

---

### Q10：重排阶段的多样性算法（DPP）

**核心答：** DPP（行列式点过程）在保证相关性的同时最大化结果集合的多样性，通过计算 item Embedding 的行列式值（几何体积）来度量集合的多样性。

**工程近似：** 精确 DPP 是 O(n³)，工业上用贪心 DPP：每次选与已选集合相似度低、自身相关性高的 item，复杂度 O(nk)（k 为已选数量）。

## 六、八股 QA：机器学习基础

### Q1：过拟合的原因与解决？

**原因：** 模型容量过大、训练数据不足、数据噪声多、特征冗余。

**解决（按优先级）：**
- 正则化：L1（稀疏，做特征选择）/ L2（权重衰减，防止极端值）/ Dropout（随机屏蔽神经元）
- 数据层：数据增强 / 增加样本 / 特征降噪
- 训练策略：Early Stopping / 学习率 Warmup+Decay
- 模型层：降低复杂度 / 集成学习（Bagging 降方差）

---

### Q2：L1 和 L2 正则化的区别？

| | L1 | L2 |
|---|---|---|
| 惩罚项 | `λ Σ\|w\|` | `λ Σw²` |
| 梯度 | `±λ`（常数） | `2λw`（与 w 成比例） |
| 解的特点 | **稀疏**（权重为 0） | **平滑**（权重趋小） |
| 适合 | 特征选择、高维稀疏 | 防止极端权重、连续特征 |
| 几何直觉 | 约束域是正方形（角点稀疏）| 约束域是圆形（平滑衰减）|

---

### Q3：BN 和 LN 的区别？

| | Batch Norm | Layer Norm |
|---|---|---|
| 归一化维度 | Batch 维度（跨样本） | 特征维度（单样本内） |
| 依赖 batch size | 是，batch=1 时退化 | 否 |
| 适用场景 | CV（CNN） | NLP / 推荐序列 / Transformer |
| 推理时 | 需存 running mean/var | 无需额外存储 |

> 推荐系统在线预测 batch=1，BN 退化，故多用 LN。

---

### Q4：AUC 的含义和局限？

**含义：** 随机选一正一负样本，正样本预测分数 > 负样本的概率（排序能力的度量）。

**局限：** ①对类别不平衡不敏感（用 GAUC 或 PR-AUC 更好）；②只反映排序能力，不反映概率校准度；③全局 AUC 可能被头部用户主导，掩盖长尾用户体验问题。

> **GAUC（分组AUC）：** 按用户分组计算 AUC 再平均，更能反映个性化效果，推荐系统常用。

---

### Q5：梯度消失 / 爆炸的原因和解法？

**原因：** 深层网络反向传播时梯度连乘——激活函数导数 < 1 则消失，权重大则爆炸。

**解决：**
- 残差连接（ResNet）：梯度有"高速公路"直接传播
- BN/LN 归一化：稳定每层输入分布
- 梯度裁剪（clip_grad_norm）：限制梯度最大范数，防爆炸
- 合适激活函数：ReLU / GELU 替代 Sigmoid/Tanh
- LSTM/GRU 门控：记忆细胞绕过多层乘法

---

### Q6：Adam 优化器原理？为什么推荐系统常用？

**原理：** 结合 Momentum（一阶矩）和 RMSProp（二阶矩），自适应调整每个参数的学习率：
```
m_t = β1·m_{t-1} + (1-β1)·g_t        # 梯度的指数移动平均
v_t = β2·v_{t-1} + (1-β2)·g_t²       # 梯度平方的指数移动平均
θ   = θ - lr · m̂_t / (√v̂_t + ε)     # 偏差修正后更新
```
**推荐系统中为什么好用：** ID Embedding 稀疏——某个用户/商品 ID 只在部分 batch 出现，其梯度大多数时候为 0。Adam 的自适应学习率让出现频率低的特征也能获得合理的更新步长，而 SGD 对稀疏特征更新效果差。

---

### Q7：GBDT vs XGBoost vs LightGBM 核心区别？

| | GBDT | XGBoost | LightGBM |
|---|---|---|---|
| 导数 | 一阶 | **一阶+二阶** | 一阶+二阶 |
| 正则化 | 无 | 有（叶子数+权重L2） | 有 |
| 树生长 | Level-wise | Level-wise | **Leaf-wise**（更快收敛） |
| 特征分裂 | 枚举 | 预排序（精确） | **直方图**（近似，快） |
| 类别特征 | 需 One-hot | 需 One-hot | **原生支持** |
| 速度 | 慢 | 中 | **最快** |

> 面试简答版：XGBoost = GBDT + 二阶导 + 正则化；LightGBM = XGBoost + Leaf-wise生长 + 直方图分裂 + 速度大幅提升。

---

### Q8：Sigmoid / ReLU / GELU 激活函数对比？

| 激活函数 | 公式 | 优点 | 缺点 |
|---|---|---|---|
| Sigmoid | `1/(1+e^-x)` | 输出(0,1)，概率解释 | 梯度消失，非零中心 |
| Tanh | `(e^x-e^-x)/(e^x+e^-x)` | 零中心 | 仍有梯度消失 |
| ReLU | `max(0,x)` | 不饱和，计算快 | Dead ReLU（负值梯度为0） |
| Leaky ReLU | `max(0.01x, x)` | 缓解 Dead ReLU | 负区间斜率是超参 |
| GELU | `x·Φ(x)` | 平滑，BERT/GPT默认 | 计算略贵 |

---

### Q9：Dropout 的原理？训练和推理时有什么区别？

**训练时：** 以概率 p 随机将神经元输出置 0，等效于训练多个共享参数的子网络（Ensemble 效果）。

**推理时：** 不 Dropout，但所有权重乘以 (1-p)（或训练时除以 (1-p) 做 inverted dropout），保持期望一致。

**为什么有效：** 防止神经元间的 co-adaptation（某些神经元过度依赖其他特定神经元），迫使网络学习更鲁棒的特征表示。

---

### Q10：交叉熵损失 vs MSE 损失，分类任务为什么用交叉熵？

**MSE 用于分类的问题：** 对于 Sigmoid 输出，MSE 梯度 `= (ŷ-y)·ŷ·(1-ŷ)`——当预测值接近 0 或 1 时，`ŷ·(1-ŷ)` 趋于 0，梯度消失，训练极慢。

**交叉熵的梯度：** `∂L/∂z = ŷ - y`（Sigmoid 后接交叉熵时梯度恰好化简为 `预测-真实`），梯度幅度与误差成正比，训练稳定快速。

---

### Q11：Transformer 中为什么要除以 √d_k？

**原因：** 当 d_k 较大时，Q·Kᵀ 的点积值方差为 d_k（假设 Q, K 各维度独立、均值0方差1），值域很大，导致 softmax 进入梯度极小的饱和区。除以 √d_k 将方差归一化为 1，让 softmax 在合理范围内工作，梯度稳定。

---

### Q12：冷启动问题的解决思路？

**新用户冷启动：**
- 引导填写偏好标签（主动获取）
- 利用设备/地理/时间等上下文特征
- 推送热门内容 + UCB 探索（Bandit）
- 迁移学习：从相似用户群迁移初始 Embedding

**新物品冷启动：**
- 利用内容特征（图文/类目/标签）构建 Content-based Embedding
- 关联相似老物品的协同信号（Item2Item）
- Bandit（Thompson Sampling）分配探索流量
- Meta-Learning（MAML）快速适应小样本

---

### Q13：在线学习（Online Learning）和离线训练的区别？

| | 离线训练 | 在线学习 |
|---|---|---|
| 数据更新 | 全量重训（小时/天级） | 增量更新（分钟/秒级） |
| 时效性 | 低 | **高** |
| 计算成本 | 高 | 低 |
| 稳定性 | 高 | 容易震荡，需正则化 |
| 算法代表 | Adam + 全量数据 | FTRL（推荐系统标配） |

**FTRL（Follow The Regularized Leader）：** 在线学习算法，同时处理稀疏性（L1正则化稀疏解）和自适应学习率（类似 AdaGrad），是工业级推荐系统在线更新的标配。

## 七、算法题速记

### 三数之和（美团一面原题）

```python
def threeSum(nums):
    nums.sort()
    res = []
    for i in range(len(nums) - 2):
        if i > 0 and nums[i] == nums[i-1]: continue
        l, r = i+1, len(nums)-1
        while l < r:
            s = nums[i] + nums[l] + nums[r]
            if s == 0:
                res.append([nums[i], nums[l], nums[r]])
                while l < r and nums[l] == nums[l+1]: l += 1
                while l < r and nums[r] == nums[r-1]: r -= 1
                l += 1; r -= 1
            elif s < 0: l += 1
            else: r -= 1
    return res  # O(n²) 时间，O(1) 空间
```

### 二叉树层序遍历（美团二面原题）

```python
from collections import deque
def levelOrder(root):
    if not root: return []
    res, q = [], deque([root])
    while q:
        level = []
        for _ in range(len(q)):
            node = q.popleft()
            level.append(node.val)
            if node.left: q.append(node.left)
            if node.right: q.append(node.right)
        res.append(level)
    return res  # O(n)
```

### 手撕 Attention（高频）

```python
import numpy as np

def scaled_dot_product_attention(Q, K, V):
    d_k = Q.shape[-1]
    scores = Q @ K.T / np.sqrt(d_k)   # [L, L]
    weights = softmax(scores, axis=-1) # [L, L]
    return weights @ V                 # [L, d_v]

# 多头：分头 → 各自attention → concat → linear
```
